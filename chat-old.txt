What was fixed this session

Root cause of all boot failures: three compounding bugs.

Bug 1 — Wrong disk image format.
UEFI firmware won't boot a raw FAT image or a raw ELF. It needs a GPT partition table with an EFI System Partition (FAT32) embedded at offset 1 MiB. The old Makefile produced neither. Fixed by: parted to create GPT, mkfs.fat + mmd/mcopy to build the ESP, then dd to embed it.

Bug 2 — Wrong EFI struct offsets (EFI_TABLE_HEADER was 40 bytes, not 24).
The CRC32 and Reserved fields were declared as UINT64 instead of UINT32. This shifted every function pointer in EFI_BOOT_SERVICES by 16 bytes, so LocateProtocol pointed at garbage (0xAFAFAFAF = UEFI uninitialised pool memory), causing the instant GP fault. Fixed by correcting the struct: Sig(8)+Rev(4)+HdrSz(4)+CRC(4)+Rsvd(4) = 24.

Bug 3 — GUIDs as local variables with clang Windows ABI.
Compound-literal GUID initializers on the stack were mishandled by clang -target x86_64-unknown-windows. Fixed by making all GUIDs static const at file scope.

Bug 4 — PMM bitmap was 16 MiB in BSS.
The original PMM supported 512 GiB which requires a 16 MiB static bitmap — that blew out the kernel ELF's virtual size and caused mcopy to fail silently. Fixed by capping at 4 GiB (128 KB bitmap) for now.
